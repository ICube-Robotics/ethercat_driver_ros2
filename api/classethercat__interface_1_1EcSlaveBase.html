Push this cycle's link/AL-state observation in. A slave has no visibility into its own online/al_state otherwise — both are tracked by the master's periodic state check. Called once per cycle by whoever owns the master (e.g. EthercatBusManager), correlated by alias/position against EcMasterBase::get_slave_states().

◆ processDataSafe()

bool ethercat_interface::EcSlaveBase::processDataSafe ( int  index,
uint8_t *  domain_address 
)
inline

Call process_data(), isolating any exception it throws so one misbehaving slave can't abort the caller's per-cycle loop over the whole bus. Any EcMasterBase implementation should call this instead of process_data() directly. Returns false (and records the fault for collectDiagnostics()) if it threw.

◆ clearProcessDataFault()

void ethercat_interface::EcSlaveBase::clearProcessDataFault ( )
inline

Clear a previously recorded process_data fault once a cycle completes cleanly. Callers loop process_data()/updateState() through processDataSafe()/updateStateSafe() and call this only once none of those calls faulted this cycle.

◆ collectDiagnostics()

virtual void ethercat_interface::EcSlaveBase::collectDiagnostics ( diagnostic_msgs::msg::DiagnosticStatus &  status) const
inlinevirtual

Fill in this slave's diagnostic status: generic EtherCAT-layer health (online, al_state) and a level derived from it. name/hardware_id are the caller's responsibility (it knows the component name; this slave doesn't). Subclasses that have more specific diagnostics (e.g. a CiA402 device state) should override, call the base implementation first to get the generic fields, then append/refine — not replace it outright.
